# LAS采集约定

## 词法与段

文件使用UTF-8，行尾可LF或CRLF。LAS2.0条目按首个点分助记符、点后到首空白为单位、其后到首冒号为值，冒号之后为说明；参数无单位时仍保留点后空白，说明中的点号与冒号不再二次拆分。以`#`起头的整行是注释，数据行不支持尾部注释。段名（`~V`/`~Version`等单字母与全称）大小写不敏感，Version段必须在最前，必须含`VERS`(2.x)与`WRAP`(YES/NO)，Well段必须含`NULL`，Curve段至少声明一条曲线。`~ASCII`之后数字按Curve段列序排列，`~Other`等新段结束当前数据区；段外条目直接报结构错误。

数字词法支持符号、小数（含`.5`/`1.`形式）与E/D指数，统一以`Decimal`解析保留精度；无法匹配词法的token按损坏处理，不按“看起来像深度”猜测同步点。

## WRAP与测点重建

- `WRAP=NO`：一条非注释数据行对应一个完整测点，列数必须等于Curve段曲线数，不足或超出即失败，不得借下一行凑齐。
- `WRAP=YES`：按曲线数跨物理行重建记录；文件结尾或新段开始时仍有未凑齐的token，按损坏失败处理，不得跨段或跨文件结尾补齐。
- 每条记录索引全部贡献token的字节区间`[start,end)`与物理行号；注释行、空行不产生测点。

## NULL、方向与重复深度

NULL按原单位的`Decimal`精确比较，不先换单位；曲线值等于NULL时保留原token并标记`null=true`，接近NULL的真实值（如`-999.2499`对`-999.25`）不得删除。深度为NULL使该文件正式索引无法完成：已完成前缀照常入库，失败位置与不完整尾写入报告，未完成文件不宣称全深度覆盖。

有效深度序列必须单调不降（down）或不升（up），方向由首个非平比较确定；同深度重测记录全部保留，按出现次序记`repeat_seq=0,1,...`，不平均、不合并。深度缺失（NULL/非法token）不可索引。头部STRT/STOP/STEP与实际观测的偏差仅作`diagnostics.mismatch`诊断，不生成不存在的测点。

## 标准深度与单位

记录保存原始深度文本与标准深度：`std = raw * depth_scale + depth_offset`，比例、偏移均为配置中的显式有理数字符串（`Fraction`精确运算），`depth_scale`必须为正。曲线别名与单位转换只认显式`curve_map`；Curve段单位必须等于映射单位或出现在`unit_aliases`中，未知单位拒绝正式转换。同文件助记符重复时按Curve列序保留，映射必须明确列号，不能只写助记符。不同井、不同run不得仅凭相同助记符拼接：查询多run时井必须相同，跨井需显式分窗。

## 磁盘索引与查询

索引为sqlite文件（runs/entries/curves/records/tokens表），构建分块读盘并逐记录写入，不要求全部曲线值驻留内存。每run记录`run_id`、源文件相对路径与SHA256、方向、记录数、完成标志、失败定位、不完整尾与诊断。查询前重算源文件SHA256，不一致即拒绝查询并要求重建。

标准深度窗为闭区间`[lo,hi]`，端点按有理数比较；正反序文件返回统一排序`(标准深度, run_id, 原记录序号)`，保留全部重测与缺测值，不插值、不合并。完整顺序抽取（`sequential`）与窗口随机读取（`query_window`）共享同一批字节区间，回读源文件可逐token核对。coverage逐run标注`complete`，不完整索引的窗口结果不宣称全深度覆盖。

domain只清点物理行，不解析Curve段或建立深度索引。
